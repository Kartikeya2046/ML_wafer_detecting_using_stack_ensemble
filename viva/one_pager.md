# Wafer Map Defect Classification — One-Page Summary

**Paper reproduced:** H. Kang & S. Kang, "A stacking ensemble classifier with handcrafted and convolutional features for
wafer map pattern classification," *Computers in Industry* 129 (2021) 103450 (Elsevier).
**Our paper:** `paper/main.pdf`.

## The problem
- A **wafer map** shows which dies (chips) on a silicon wafer passed or failed testing.
- Failed dies form **patterns** (Center, Donut, Edge-Loc, Edge-Ring, Loc, Random, Scratch, Near-full, or None). Each
  pattern points to a different fault in fabrication, e.g. a ring at the edge suggests an etching/deposition problem at
  the wafer rim, and a scratch suggests mechanical handling.
- Dataset: **WM-811K**, 172,946 labeled wafers, 85% are "None", so we report **macro-F1** (every class counts equally),
  not just accuracy.

## What the original paper does
1. **Handcrafted features → small neural network (MFE+FNN):** 59 numbers per wafer: defect density in 13 regions, 40
   Radon-transform profile values, 6 shape measures of the biggest defect blob.
2. **CNN (VGG16, ImageNet-pretrained)** looks at the 64×64 wafer image directly.
3. **Stacking with MLR:** a ridge regression learns, *for each class*, how much to trust each of the two models.
   Handcrafted features are better at Random/Near-full; the CNN is better at Edge-Ring/Scratch, so combining helps.
- Reported result: macro-F1 **0.8949**.

## What we did
| Part | Result |
|---|---|
| **Reproduced all 6 models** of the paper (full data + training sizes 500 / 5,000 / 50,000) | Stacking-MLR **0.8967** vs 0.8949 reported; all six models match or beat the paper at full data |
| **Found a pitfall** | Training the stacker on the models' predictions for their *own training data* (as the public code does) makes it ignore the rarest class (Near-full F1 = 0). Fix: train it on a held-out split *B*. |
| **Test-time augmentation** (average the CNN over 8 rotations/flips) | small but significant gain, no retraining |
| **XGBoost on the 59 features** | a better handcrafted-feature model than the paper's FNN |
| **5-CNN ensemble** | biggest gain of all |
| **Final pipeline: 5 CNNs (TTA) + XGBoost → MLR** | **macro-F1 0.9134**, accuracy **98.21%** |
| **Reject option** (send unsure wafers to an engineer) | 95.2% of wafers classified automatically at **99.72%** accuracy |

## Honest negative results (say these confidently — they show rigor)
- With a 5-CNN ensemble, the paper's handcrafted-feature FNN **no longer helps**.
- Adding a *different* third model (XGBoost) was not better than adding a *second copy* of an existing model.
- Under the paper's own training protocol, the stack does **not** beat the CNN at N = 50,000.
- Temperature scaling did not improve calibration of the MLR stack.

## How we kept it fair
- All decisions on validation split **B**; test set only for reporting.
- Paired t-tests + bootstrap confidence intervals over wafers; a fixed rule for keeping an extension.
- Every number in the paper is generated by a script from saved results (`paper/make_assets.py`).
